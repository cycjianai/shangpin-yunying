# 牵牛花搬品冲突回退复核合同 v1

## 1. 适用场景与范围

源表是固定的“新增前后映射”工作簿，至少包含旧商品、目标商品、处理结果以及 J/K 回填列。任务集合只能由处理结果列产生：

- `条形码变化`
- `商品名称变化`
- `商品名称变化+条形码变化`

不得把`成功`行、空行或全量主档成员扩成待复核任务。全量或历史销售规格导出可以作为只读检索索引，但完成统计的分母始终是上述
三类行的冻结数量。

## 2. 精确回退规则

先用目标 SKU 读取当前迁入商品，再按处理结果逐字段执行：

- 名称变化：当前名称必须以数字 `1` 结尾；只删除这一个字符，剩余文本是查询前缀。名称可能受平台长度上限影响，出现
  `原名称…/个 → 迁入名称…/1`，不得擅自补回被截断的`个/瓶/袋/包装`，只能用已验证前缀搜索。
- 条码变化：每个当前目标条码必须以数字 `1` 结尾；每个条码只删除一个末尾 `1`，所得完整条码用于精确搜索。
- 两者变化：两条规则分别执行，不能只回退其中一个字段。
- 只删除末尾字符；名称或条码内部的 `1`、原值本来结尾的 `1`、以及末尾不是 `1` 的值都不能改。

若当前值为 `…112 / …122 / …132`、空值、目标 SKU 已不存在或其他无法“一次删 1”还原的状态，失败关闭，在 J 列写固定原因，
禁止改成删除多位、使用模糊条码或猜测原值。

## 3. 候选与同品判定

1. 候选必须当前仍存在；迁移前快照只能证明历史冲突来源，不能代替当前存在性。
2. 排除同一迁移清单中的全部目标 SPU/SKU，不能把新迁入商品或它的其他规格当作原商品。
3. 条码相同只是候选线索，不是同品结论。品牌明确冲突、商品主体不同或规格冲突时必须判为不同商品。
4. 名称允许营销词、词序、单位写法和包装描述轻微不同，但商品主体必须一致。
5. 多规格商品必须唯一落到与旧规格一致的 SKU；尺码、颜色、容量、数量、口味或包装量冲突时不匹配。
6. 多个候选无法唯一裁决时不猜，写`存在多个原商品候选，规格无法唯一对应`。

## 4. 固定工作簿 Schema

保持源工作簿所有工作表、行序、公式、样式和已有字段不变，只写：

| 条件 | J 列“一样的商品sku” | K 列“一样的商品条形编码” |
|---|---|---|
| 唯一确认同品同规格 | 当前仍存在的原 SKU，文本 | 该原 SKU 当前条码，文本 |
| 未匹配或不确定 | 固定原因 | 空 |

固定原因前缀只有：

- `当前主档未找到仍存在的原商品候选`
- `当前主档未找到目标SKU，无法执行末尾1回退复核`
- `目标条码不符合“末尾加1”规则，无法按指定方式回退`
- `原商品候选名称不一致，无法确认是同一商品`
- `原商品候选品牌不一致：…`
- `原商品候选规格不一致：…`
- `存在多个原商品候选，规格无法唯一对应`

ID 和条码必须按文本写入。未进入 manifest 的行 J/K 原值必须逐单元格保持不变。

## 5. 完成门

- manifest 数量与三类变化行计数完全一致，其他行处理数为 0。
- manifest 每行 J 非空；匹配行 K 非空，原因行 K 为空。
- 匹配行的 J/K 来自同一个当前原 SKU；不存在目标 SKU、自身 SKU 或同批迁入 SKU 回填。
- 非目标 J/K 变化数为 0；全工作簿公式变化数为 0；新增公式错误数为 0。
- 保存后独立重开回读，并渲染至少一个匹配样例和一个原因样例检查列位与格式。
- 报告必须分开列出匹配数、原因数、末尾 1 规则异常数和目标 SKU 缺失数，合计等于 manifest。
