# 渠道不可售审核报错策略

每次冻结后先运行 `build_error_strategy_matrix.py`，保留逐 SPU 审核原文，再按以下顺序合并为一次提交计划。

| 报错类型 | 自动处理 | 证据门 |
|---|---|---|
| 平台明确属性建议 | 字段对齐、候选合法且无标题/规格冲突时直接写；当前值相同不重复保存 | 审核原文、当前类目候选、商品事实 |
| 缺品牌/规格/功率 | 从当前品牌字段、SKU、铭牌补标题 | 同 SPU 可见事实 |
| 缺详情图 | 详情为空时仅复用当前商品（或当前门店）自身已有主图 | 不跨 SPU；永久禁用 `6f244c5f...` / `064b297f...` 等通用占位图；禁止对含自定义图片的门店发送 `{ field: 'picture', coverToStore: 1 }` |
| 主图水印、空图、模糊、主体问题 | 严禁用 `query-pics-by-sku-name` 模糊搜图或通用占位图替换商家原有主图；仅在有同 SPU 真实同款实拍图时按门店自定义隔离规则处理 | 品牌、型号、规格、图案均一致；若门店已开启自定义图片（`customizedPicFlag: true`），严禁改为跟随总部或主档级联覆盖，必须按门店独立维护 |
| 配料/营养图 | 先复用真实同款背标；必要时按正式模板做清晰化，生成后 OCR/目视逐字核对 | 配料、营养、条码及规格一致；严禁填入 `pictureExample` 示例图 |
| 包装标签/背签 | 使用同款真实标签或参考图清晰化；背签使用唯一 canonical 五项提示词 | 厂名、厂址、型号、执行标准、许可证可追溯 |
| 尺寸图 | 优先镜像同 SPU 真实尺寸图；缺图时可从官方型号或当前包装中的明确尺寸生成标注图 | 不估算尺寸，多规格分别核对；审核原文明报缺图但详情漏槽位时只允许构造 13 号尺寸图槽位 |
| 条码 | 扫同 SPU 图片或权威精确同款搜索；校验 GTIN 和规格 | 品牌、品名、容量/件数一致 |
| 3C | 博查/CQC 按品牌+精确型号查询并核对制造商 | 16 位真实证书编号和有效证书；查不到不写固定值 |
| 化妆品/医疗/检验报告 | 只复用真实监管材料 | 官方登记或真实证照 |
| 禁售/超经营范围/缺资质 | 停止自动提交并转人工资质/类目处理（`manual_block`） | **严禁通过跨品类改名、篡改类目（如改为“便当盒/保温杯/厨房储物器皿”）或篡改品牌（如改为“海尔”）规避拦截！** |
| 价格同步失败/低于起购价/价格异常 | 停止自动改价并转人工核对（`manual_block`） | **非调价任务严禁改动任何价格字段（`storePrice` / `unifiedOnlinePrice` / `sellingPrice`）！** |
| 门店自定义商品（`customizedNameFlag: true` / `customizedPicFlag: true`） | **严禁强制改为“跟随总部”或用主档 `coverToStore: 1` 级联覆盖** | 必须调用 `/qnh-gw3/api/product/store/update` 按该门店当前自定义的名称、主图、分类独立维护该门店商品！ |

## 执行器路由

先按审核原文确定路由，再生成每个 SPU 的合并计划：

| 路由 | 适用问题 | 固定实现 |
|---|---|---|
| `safe_direct` | 平台明确建议、标题/SKU/同渠道已存在的普通事实 | 直接生成 expected-old 计划，保存后逐字段回读 |
| `bocha_resolve` | 普通信息字段缺失且页面没有确定答案 | 复用项目 `product_fill_resolution` 的博查搜索、字段键解析和 `_validated_resolution`；每个业务键一次搜索、一次解析 |
| `reference_generate_or_reuse` | 配料营养、背签、包装标签、尺寸、纺织说明等图片 | 复用项目正式提示词和 provider 状态机；绑定同款参考图/可核验事实，一次 submit、只 query 原任务，目视/OCR 后上传 |
| `regulated_evidence_only` | 3C、化妆品/医疗备案、生产许可、检验报告、公章材料 | 博查或权威登记只用于寻找现有真实材料；查不到就阻塞，禁止生图或固定值 |
| `manual_block` | 禁售、超经营范围、账号缺少经营资质 | 保留原文并转人工，不通过改名、换图或猜类目规避 |

博查返回值只能进入当前页面候选/字段合同允许的普通字段。`provider_unresolved`、证据合同拒绝或商品身份
不唯一时，记录一次终态后不重复查询。图片生成成功、上传成功、保存成功和审核退出必须作为四种独立状态。

## 专项图槽位与错槽审计

写图前同时核对实时 `pictureType/title/description/numLimit`。已验证默认映射：3 包装标签/参数、
4 3C/品质、5 配料营养、6 纺织使用说明、7 吊牌/洗唛、8 背签、13 尺寸。背签与包装标签不得互换；
曾有背签批量落入 3 号槽，导致顶层接口似乎有图但 8 号背签仍被审核判空。

先查同 SPU 是否已有相同制品落错槽。若有，复用原牵牛花 URL 迁移到 canonical 槽位，不再次生图或上传。
同一槽位需要多张互补图时先合并最终 URL 集合，只发一次保存。保存证据必须同时覆盖实际请求、独立详情回读；
详情与编辑页不一致、标品库限制或保存零请求时，还必须刷新/重开编辑页确认正确槽位仍可见。

## 审核反馈闭环

每轮保存后按 SPU 对比写前/写后审核原文，状态固定为：

- `materialized_waiting_review`：字段或 URL 回读一致，但平台仍在审核。
- `exited_unavailable`：从原筛选集合退出。
- `same_reason_still_present`：原原因仍在，先核对字段路径、图片槽位、门店覆盖和写回值，不重复保存相同内容。
- `new_reason_after_review`：原原因消失、出现独立新原因，只为新原因建立增量计划。
- `blocked_without_evidence`：没有同款真实证据或监管材料，停止自动提交。

立即快照只用于观察趋势；至少取得两份 SPU 集合哈希一致的快照后才报告稳定数量。平台审核可能需要
数分钟至 1–2 小时；等待期间只 query/read，不重复 provider submit 或平台 save。

批次审核效果按本批目标 SPU cohort 计算，并另报平台总量、新进入 SPU 和原始 manifest 交集。只用页面总数
前后相减无法判断本批退出数，也不能用另一 CDP/tenant 的数字回答当前账号。

同一商品的普通属性、标题、条码、主图、详情图和专项图先合并为一个 `one-pass` 计划。一个专项图槽位需要多张互补图片时，先生成最终 URL 集合，只保留一条目标变更再保存。

正式专项图生成必须持久化业务幂等键、provider、调用类型和 `provider_task_id`。上游一旦接单，只查询原任务；`ready/uploaded` 不等于牵牛花交付，上传后仍要保存并逐槽位回读。

同一型号在不同区域可能使用不同电压、插头、电源线和 GTIN；官网全球版只能作为候选证据。当前 SPU
包装、铭牌或详情参数图存在更具体值时，以同 SPU 值为准，并立即纠正已写的区域冲突字段。

无条码保存后若新增证据表明商品有明确品牌、型号或独立零售包装，立即按写前快照受限回滚；
只有当前状态仍等于本轮写入结果时才允许恢复，避免覆盖后续人工修改。

批量预演必须显式传 `--dry-run`；预演检查点只能出现 `previewed/no_change`，
不得出现 `verified`，也不得生成保存结果文件。入口不识别预演参数时停止批次并先修复执行器。

断点结果路径归一化必须用单参数包装调用 `path.resolve`，禁止把它直接作为
`Array.map` 回调；后者会把数组索引和原数组一并传入，导致批次在任何平台请求前
以 `paths[2]` 类型错误失败。修复后先跑语法检查和双条预演，确认零保存再恢复正式批次。
# 批次预校验必须早于任何付费协程

当同批某个任务因标题或提示词包含 3C、证书、备案、注册证、医疗器械、公章等内容而禁止生成时，必须在创建任何 provider 协程、选择渠道或发出 HTTP submit 前先完成整批同步校验。违规任务写入 `validation_rejected + call_type=not_sent`，其余合法任务才进入并发执行。

如果旧进程已留下 `prepared` 但没有 `provider_task_id` 的回执，不能直接视为未接单。恢复前必须同时确认该回执没有 `provider_key`、没有 `provider_stage`、没有 provider 日志中的 `selected/submitted`，并且没有任何远端受理凭证；证据不全时转人工。已有远端任务号始终只查询原任务，不能因规则变化、进程重启或提示词调整重发。

批次统计必须分别保留 `ready`、`terminal_failed`、`validation_rejected`。上传数量只等于 `ready` 制品数；`validation_rejected` 不计付费请求，`terminal_failed` 已产生远端任务号但禁止自动重提。
