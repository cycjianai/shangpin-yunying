# 统一运营回传 Excel Schema v1

Schema ID：`product-governance-operations-workbook-v1`。机器唯一真源为
`scripts/operations_workbook_schema.json`。

## 适用范围

四个平台（牵牛花、美团、翱象、淘宝闪购）与两类任务（属性信息、资质图）必须返回完全相同的工作表顺序、表头和
汇总指标。平台适配器只负责把结果映射到统一行模型，不得新增、删除、改名或重排运营字段。

属性字段与资质图槽位使用同一审计模型：资质图的 `pictureType/slotId` 写入 `字段ID`，平台显示槽位名写入
`字段名`，`渠道` 写目标渠道或图片槽位组，执行前/计划值/最终回读值记录低敏图片标识或结果说明。

## 固定工作簿

文件名固定为 `MMDD{门店或租户可见名称}{源清单唯一SPU数}.xlsx`。输出只允许以下 7 张工作表：

1. `执行汇总`
2. `SPU清单`
3. `字段级审计`
4. `平台不存在`
5. `最终结构复核`
6. `问题与策略回灌`
7. `性能与外部调用统计`

源文件仅作为只读输入；不得把来源各异的业务工作表复制进运营回传表。源表 B/C 中已有可信历史可按 SPU 合并到统一
`SPU清单`，其他输入工作表保持在原文件，不进入交付文件。

精确表头以 JSON 真源为准：

- `执行汇总`：`指标`、`结果`
- `SPU清单`：`SPUID`、`执行前缺失/无效字段`、`本次实际填充及最终回读`
- `字段级审计`：`SPU编码`、`商品名称`、`渠道`、`字段ID`、`字段名`、`执行前`、`计划值`、`最终回读值`、`结果`、`来源策略`
- `平台不存在`：`SPU编码`、`平台结果`、`处理口径`
- `最终结构复核`：`指标`、`结果`
- `问题与策略回灌`：`本次新情况`、`修正规则`、`验证结果`
- `性能与外部调用统计`：`指标`、`结果`

## 统一内容口径

- B 列逐 SPU 写执行前缺失、无效属性或不合格图片槽位；C 列写实际处理内容和保存后独立回读结果。
- 未修改商品也必须写执行前已满足合同、无需修改和最终回读通过，禁止空 B/C。
- 平台不存在商品保留在 `SPU清单`，并在 `平台不存在` 单列，不计入平台现存完成率分母。
- `执行汇总`、`最终结构复核` 与 `性能与外部调用统计` 的指标名称和顺序必须精确等于 JSON 真源；不适用指标填 0，
  不得删行或增加平台专属指标。
- 属性任务的“操作项”是一条字段变更；资质图任务的“操作项”是一条图片槽位处理。两者都以最终独立回读通过计完成。
- 每次任务只替换商品、执行前值、计划值、最终值、数量、耗时和策略等数据，不改变模板结构。

## 机器验收

所有平台导出器与 validator 必须读取同一个 `operations_workbook_schema.json`，禁止各自复制表头常量。Schema、工作表
顺序、表头、汇总指标顺序、SPU 集合、B/C、审计对账或版本指纹任一不符时返回非零，文件不得交付。

validator 只证明表内结构正确；对用户交付还必须通过对应平台的完成门和交付门，证明工作簿来自同一 execution run。
