# 统一运营回传 Excel Schema v1

Schema ID：`product-governance-operations-workbook-v1`。机器唯一真源为
[`scripts/operations_workbook_schema.json`](../scripts/operations_workbook_schema.json)；单元格词汇和字段 ID 规则见
[统一输出内容合同](core/output-contract.md)。

## 适用范围

五个平台（牵牛花、美团、饿了么、翱象、淘宝闪购）与全部任务模式必须返回完全相同的工作表顺序、表头、汇总指标、
字段顺序和内容词汇。包括属性、资质图、不可售、插件、搬品重试、调价、商品编辑和医疗器械整店迁移。

平台适配器只把本平台事实映射为统一事件，不得新增、删除、改名或重排运营字段。资质图把槽位映射为字段；调价把每个
SKU 的价格/活动映射为字段；迁移把目标身份与字段组映射为字段；搬品九项映射只作内部证据，不是另一种交付模板。

## 固定工作簿

文件名固定为 `MMDD{门店或租户可见名称}{源清单唯一SPU数}.xlsx`。输出固定且仅有以下 7 张工作表：

1. `执行汇总`
2. `SPU清单`
3. `字段级审计`
4. `平台不存在`
5. `最终结构复核`
6. `问题与策略回灌`
7. `性能与外部调用统计`

源文件始终只读；不得复制来源各异的其他工作表到运营交付文件。可信历史只按 SPU 合并进 `SPU清单` B/C 和字段级
审计事件，不能改变模板结构。

精确表头以 JSON 真源为准：

- `执行汇总`：`指标`、`结果`
- `SPU清单`：`SPUID`、`执行前缺失/无效字段`、`本次实际填充及最终回读`
- `字段级审计`：`SPU编码`、`商品名称`、`渠道`、`字段ID`、`字段名`、`执行前`、`计划值`、`最终回读值`、`结果`、`来源策略`
- `平台不存在`：`SPU编码`、`平台结果`、`处理口径`
- `最终结构复核`：`指标`、`结果`
- `问题与策略回灌`：`本次新情况`、`修正规则`、`验证结果`
- `性能与外部调用统计`：`指标`、`结果`

## 统一内容口径

- B 列逐 SPU 写执行前问题；C 列写本任务实际处理、独立回读和最终终态。未修改商品也必须写终读结论。
- 平台不存在商品保留在 `SPU清单` 和 `平台不存在`，从平台现存完成率分母剔除。
- `执行汇总`、`最终结构复核` 和 `性能与外部调用统计` 的指标名称与顺序精确等于 JSON 真源；不适用指标填 0。
- `执行平台`、`任务类型`、`结果`、`来源策略`、空值、金额、时间和多值序列化严格使用机器 Schema 的固定词汇。
- `唯一操作项数` 固定等于 `字段级审计` 非空数据行数（包含显式阻塞/待核验事件）；`最终回读通过项数` 只统计机器
  Schema 登记的 readback-pass 终态；`最终合同通过商品数 + 最终问题数 = 平台现存商品数`，完成率据此重算。
- 每次任务只允许事实数据、数量、耗时和策略变化，模板结构与固定词汇不可漂移。

## 机器验收

新任务优先使用共享导出器和 validator：

```bash
python3 scripts/core/export_operations_workbook.py --input "$PAYLOAD" --output "$OUTPUT_XLSX"
python3 scripts/core/validate_operations_workbook.py --workbook "$OUTPUT_XLSX" --output "$VALIDATION_JSON"
```

现有平台兼容 exporter 仍须读取同一个 JSON Schema，并在平台完成门前通过共享 validator。Schema、工作表顺序、表头、
指标顺序、固定词汇、SPU 集合、文本 ID、B/C、审计对账或版本指纹任一不符时返回非零，文件不得交付。

`copy_history_retry` 不得另交专用 9 列工作簿。所有商品执行表都必须来自同一 execution run，并通过当前平台完成门与
handoff gate；PoC、只读审查、抽样复核或人工挑选的“最新 xlsx”不能冒充权威交付物。
