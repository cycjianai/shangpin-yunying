# 字段证据与安全边界

## 可自动填写

满足“候选值存在且商品事实明确”时，可自动填写：

- 商品类型、包装方式、口味、储存方式、是否含糖等普通属性。
- 同一商品其他渠道已有的等价类目和属性。
- SKU 已有净含量及单位，且数值范围合理、单位转换无歧义。
- 标题去除平台明确禁止的符号，或补充商品规格中已存在的净含量。
- 卖点删除医疗、保健、减肥等无证据功效，或改写为标题/规格中已经存在的客观功能。
- SKU 规格名称按同一商品清晰图片、标题和现有规格之间的唯一事实纠正包装、容量或数量。
- 条码来自同一 SPU 图片，或权威页面逐字匹配品牌、完整品名和精确规格，并通过 GTIN-8/12/13/14 校验位检查。
- 平台官方推荐且与商品标题、类目不冲突的属性。

## 必须阻塞与绝对禁区（严禁触碰）

没有同一商品真实证据时，不自动填写或生成：

- 厂名、厂址、产地、生产许可证、执行标准。
- 进口国、报关、中文标签、境内责任人。
- CCC 编号和证书图。
- 化妆品备案/注册编号、特殊化妆品资质。
- 医疗器械注册/备案、药械资质。
- 品牌授权、商标权属、质检报告。
- 法定资质图、营养标签图、商品包装信息图。
- 近似型号、不同容量/颜色/地区版本的条码；无法证明“确实无条码”时也不能自动勾选无条码。

### 🔴 牵牛花门店自定义与核心商业字段防篡改铁律

1. **严禁强制将门店自定义改为“跟随总部”或主档级联覆盖自定义门店**：
   - 在牵牛花中，同一主档 SPU/SKU 在不同门店可能开启了自定义名称（`customizedNameFlag: true`）或自定义图片（`customizedPicFlag: true` / `customizedPicUrlListFlag: true`），甚至在不同门店代表完全不同品牌或款式的商品。
   - **绝对禁止**将门店的 `customizedNameFlag` 或 `customizedPicUrlListFlag` 从 `true` 改为 `false`（强制改为跟随总部）；
   - **绝对禁止**在主档 `tenant/update/v2` 中对含自定义门店的商品发送 `{ field: 'spu_name', coverToStore: 1 }`、`{ field: 'product_name', coverToStore: 1 }`、`{ field: 'picture', coverToStore: 1 }` 或 `{ field: 'pic_url_list', coverToStore: 1 }`（会触发 `主档级联更新` 静默清零全门店自定义！）；
   - 有自定义信息的门店必须以门店为单位，调用 `/qnh-gw3/api/product/store/update` 按该门店当前的自定义名称、自定义主图（`picInfoList`）、自定义分类独立维护。
2. **严禁通用占位图与图库模糊搜图覆盖原图**：
   - 永久禁用 `6f244c5f3cb8b26399bbf31116c40de81422507.png`、`064b297f2dffbf5ad8d0e51e6f35cd5b1391479.png` 等通用服务说明/温馨提示图；
   - 严禁用 `query-pics-by-sku-name` 模糊搜图结果替换商家原有主图；严禁把 `pictureExample` 示例图写入特殊图槽位。
3. **严禁跨品类改名/改类目/改品牌规避资质拦截**：
   - 严禁因医疗器械、成人用品、3C 或超经营范围拦截，把正常商品类目篡改为 `便当盒 / 保温杯 / 厨房储物器皿` 或把品牌篡改为 `海尔`。
4. **非调价任务价格零触碰与上下架状态保护**：
   - 非调价任务严禁改动主档 `erpInfo.sellingPrice` 及门店 SKU 的 `storePrice`、`unifiedOnlinePrice`、`channelOnlinePriceList`；
   - 严禁将原本已下架（`spuSaleStatus: 2` / `saleStatus: 2`）的商品擅自改为上架（`1`），严禁将已发布渠道置为 `-1` 删除；
   - 写前必须落盘主档 `tenant/detail` 与全部关联门店 `store/detail` 的完整 JSON 快照。

“看起来像”“同类商品通常如此”“LLM 认为大概率”都不构成合规证据。

## 无条码兜底边界

平台原生“此商品没有条形码”只适用于无明确品牌、型号和独立零售包装的通用商品。必须同时保留：

- 至少 3 张同 SPU 图片全部读取成功、ZXing 未识别出有效 GTIN 的逐图结果。
- 人工目视确认图片没有条码、品牌或型号冲突。
- 完整标题与规格的精确网页检索记录；搜索只出现多品牌相似款或没有唯一同款。
- 当前错误值与内部 SKU/商品编码的对应关系。
- 保存后 `upcList=[]`、`goodsUpcList=[]`、`customizeNoUpcCode=1` 的逐字段回读。

食品、饮料、化妆品、医疗器械、明确品牌商品和有独立零售包装的商品不得使用此兜底。
扫描没有识别到条码只是必要条件，不是单独充分条件。

## 图片复用条件

图片优先来自同一 SPU 的现有主图或详情图。牵牛花图库候选只能通过当前商品完整标题查询，
并且不能把查询命中本身当成同 SPU 证明。自动采用前需同时满足：

1. OCR 或人工检查能完整读到目标材料中的关键字段。
2. 图片不是宣传图、占位图、拼接错误图或与当前规格不符的图片。
3. 资质类型与页面要求完全一致。
4. 保存后回读 URL/图片类型一致。
5. 图中文字中的型号、长度、容量、颜色、包装形态与当前标题和规格不冲突。
6. 图库图片还必须命中当前商品品牌/品名词；重复“售后/提示”通用图不能作为主图或专项图证据。

识别置信不足、文字残缺或图片与规格矛盾时，标记人工补材料。

生成式图片只能用于非监管类视觉，且不能生成未经实物证据支持的标签事实。CCC、医疗/化妆品
注册备案、检验报告、公章、许可证等官方材料永远不得生成或冒充；已有真实材料可按上述条件复用。
所有可维护的资质图生成、真实材料 OCR、上传和写回限制统一由
`scripts/qualification_image_policy.json` 执行；字段说明见 `qualification-image-policy.md`。

## LLM 使用边界

LLM 只能从页面候选中选择，不得自由编写合规事实。请求上下文只包含低敏商品标题、类目、规格、候选项和现有属性；不发送 Cookie、签名、手机号或完整接口请求。

输出必须包含：

- 目标字段及候选值。
- 支持该选择的商品原始事实。
- 置信度。
- 无法确定时返回 `blocked`，不能强行给值。

低于预设置信度或证据无法逐字对应商品原始信息时不提交。

## 保存与审核口径

- 商品名称、卖点、规格、条码、渠道属性和图片应先合并到同一 SPU 的单次更新计划。
- 保存后必须重新读取目标字段并逐值比对；HTTP 200 或业务码 0 不能代替字段回读。
- 回读通过表示写入已物化，不表示平台异步质量/合规审核已经通过。
- 审核期间不重复提交相同值。复扫时只处理平台新返回且有新证据的原因。
