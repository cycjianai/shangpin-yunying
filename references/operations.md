# QNH 浏览器与执行器运行手册

## 会话与登录

先发现可用浏览器，复用用户已授权账号的登录态并核对 tenant/store、目标页面与实际执行占用。
新的独立任务创建 run-dir；断点恢复沿用原任务记录。不要因任务有历史 checkpoint 就直接判会话忙碌，
也不要因登录失效自动更换 profile。不能抢占其他任务的页面或执行权。

需要登录窗口时，优先通过当前环境的本机代理打开现场探测到的 loopback noVNC 地址。
代理不可用时再采用 SSH 本地转发，仅转发登录窗口所需端口，不默认转发 CDP，不硬编码映射端口。
临时公网隧道须有明确知情授权且用完关闭。密码与验证码由用户在浏览器输入。

只有没有可复用会话或用户要求新建时才运行 `scripts/start_qnh_browser.sh`。
显式传入本次 profile、日志目录、空闲 display/CDP/VNC/noVNC 端口和实际 Chrome 路径。
CDP、VNC、noVNC 仅监听 loopback。脚本默认值不是当前运行配置或登录入口。
Linux 启动依赖项目受控入口，可用 `QNH_RUNTIME_GUARD` 指定等价入口；不可用时说明依赖，不裸跑或伪造 managed 标志。

## 按任务保留证据

保留身份、授权范围、起始目标集合、计划、写意图/受理回执、独立回读、checkpoint 和最终统计。
仅当任务实际涉及图片、OCR、条码、推荐或标准报告时生成相应制品；不要为总部价格导入生成无关的图片扫描记录。
不保存 Cookie、签名、Authorization、验证码或完整请求头。用户数据留在任务目录，不进入 Skill 仓库。

## 两种执行路径

- 总部零售价导入按 [价格补齐任务](tasks/qnh-headquarters-price-fill.md)：同页分页、一次货盘匹配、官方模板、
  少量批次导入、独立回读；模板行数上限不等于 editor worker 并发。
- 既有完整对象执行器的 `apply-direct-batch` 通过 `scripts/run_qnh_batch.sh`，显式传稳定 `--offset`、
  `--limit 1..50`。每个目标 SPU 要有精确编辑页证据；同 SPU 串行、批次完成后按原 checkpoint 续跑。

资源检查、热页复用和并发见 [资源合同](runtime-resource-contract-v1.md)。现场宿主的 slice、内存和 swap 阈值
以实际运行配置为准。只清理本任务拥有的临时页；不得在批次开始时无差别关闭用户编辑标签。

## 异常与完成

- 登录或身份变化：暂停发送，保留原意图，恢复同一授权账号后预检和续跑。
- 写入未知：先查原任务与字段物化，不能用超时、列表暂时无变化或一个观察窗口无进展推断未执行。
- 只读失败：分类后有界重试；429 遵守平台退避提示，403 核对当前身份与同文档签名。
- 审核中：物化与审核退出分开统计，在任务约定的有界窗口内复扫，未退出如实报告。
- 单商品明确校验失败：保留原因，继续独立商品；修正后只处理已确认需要补写的残余。

最终汇报按用户目标给出起始数、独立核验成功数与剩余数。不可售任务另报审核等待，价格任务另报 SPU/SKU 口径；
不把所有任务都套成不可售或资质图报告。
