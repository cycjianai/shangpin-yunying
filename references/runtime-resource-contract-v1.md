# 浏览器与批处理资源合同

当前项目的资源规则和实际受控运行入口优先。不要把某台宿主的绝对内存值、slice 名称或历史峰值当成所有环境的准入门。
本包的机器策略是 [`scripts/runtime_resource_policy.json`](../scripts/runtime_resource_policy.json)。

## 新工作准入

新浏览器及批处理使用项目已有受控入口；本包两个 shell 启动器支持 `QNH_RUNTIME_GUARD` 指定等价入口。
缺少入口时说明具体依赖，不伪造 managed 标志。复用已登录会话前核对平台、账号、门店和当前占用，不重启其他任务的浏览器。

批次前与批次间检查 `MemAvailable / MemTotal >= 10%`，持续观察当前任务及浏览器占用。
共享策略不额外要求绝对内存余量或固定进程 RSS；现有执行器和宿主的实际资源边界仍由各自运行配置执行。
指标缺失或不可信时延后新工作。资源不足只暂停领取和创建，保留进度，不停止其他业务进程或修改共享资源配置。

## 页面与并发

默认一个可复用热 writer，先批量查询和本地规划。现有执行器支持 `1→2→4`，4 是本包 writer 上限，
并非平台通用限额，也不代表一次只能导入四行。官方批量入口按其模板行数限制执行。
只有同量端到端实测更快、失败率不升且资源健康才升档；压力出现后本轮只降不升。
同一 SPU 的完整对象写入始终串行，未知结果先回读。

控制页最多 2 个、引导页最多 1 个、writer 最多 4 个是本包执行器的页面预算。
引导页在 writer 启动前关闭；禁止每个商品永久累计标签。只回收本任务明确拥有的临时页，不关闭用户页或其他任务页。

## 证据与完成

使用本包机器执行器时，按其动作合同生成真实的 `runtime-resource-admission.json` 和
`runtime-resource-summary.json`，由对应完成门验证。`runtime_guided` 官方界面流程记录实际受控运行、
内存检查及页面回收证据，不能伪造旧执行器动作收据来凑门禁。

速度统计包含读取、规划、上传、保存、独立回读和任务要求的交付阶段。配置并发、按钮间隔、单段耗时不能冒充端到端速度。
