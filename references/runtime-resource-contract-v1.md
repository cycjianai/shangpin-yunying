# 全平台运行资源合同 v1

本合同是所有平台、所有任务模式在浏览器读取、OCR/图片治理、平台写入和断点续跑前的共同前置门。机器唯一事实源为
[`scripts/runtime_resource_policy.json`](../scripts/runtime_resource_policy.json)。平台模块可以设置更低上限，不得放宽共同硬门。

## 1. 先准入，后启动

每个 run 在启动新浏览器、创建新标签/frame、恢复 checkpoint 或执行首个页面读取前，先冻结：宿主总内存、
`MemAvailable`、任务进程 RSS、现有浏览器及任务自有页面数、其他活跃任务和受管运行状态。把低敏指标交给
`runtime_resource_policy.py validate`，输出 `runtime-resource-admission.json`。

准入不通过时只延后当前任务，保留 manifest/checkpoint，不关闭其他浏览器、Worker、业务进程或用户标签页。指标缺失、
统计失败和任务页面归属不明均视为不通过；禁止用“应该够用”继续扩量。

## 2. 标签页与 worker 硬门

- 默认只使用一个可复用热 writer 页；先批量走同页/接口 query-only，避免为每个商品创建页面。
- 只有相同商品量 canary 证明端到端墙钟更短、失败率不升、回读完整且资源余量持续通过，才按 `1→2→4` 升档。
- 4 个 writer 是单任务全平台硬上限；平台合同写 6/8/10 或命令传更高配置时，以本合同 4 为准。
- 控制/列表页最多 2 个。临时引导页最多 1 个，而且必须在真实 writer 启动前关闭；引导页和 writer 不得同时累计。
- 禁止一商品一标签、永久保存已终态商品页面、按重试次数叠加页面或在恢复时重建已完成窗口。
- 商品终态后立即清理大对象并复用或关闭其执行上下文；任务结束时，自有页面必须回落到基线加必要控制页。

## 3. 内存与降档

准入同时保留机器策略中的绝对内存余量和宿主比例余量，取更严格者。任务进程 RSS、任务页面预算或宿主余量触门时：

1. 停止创建新页面和领取新商品；
2. 持久化 checkpoint/write intent；
3. 关闭临时/空闲任务页并回收当前任务大对象；
4. 将后续 writer 上限单调降为下一档，压力出现后不得在同一 run 再升档；
5. 余量仍不足则延后原 checkpoint，不把资源准入失败记成商品失败。

禁止为了本任务速度停止其他业务进程、抢占其他活跃会话或把 cgroup 硬回收当正常批次循环。批量进程必须进入项目受管
运行入口；无法证明受管时零平台读取与写入。

## 4. 速度口径

速度优化只接受端到端总墙钟改善，统计必须包含源商品数、读取、规划、上传、保存、独立回读、复扫、导出与完成门。
配置并发、按钮间隔、保存突发速度或排除失败项后的样本均不得冒充速度。更高并发若没有更快，立即粘滞使用更低档；
单热页更快时就固定单热页，不为追求名义并发增加标签和内存。

## 5. 平台注册与完成门

每个 `implemented` 模块必须：

- 在合同指纹中冻结资源策略与本参考文件 SHA-256；
- 把 `runtime_resource_admission` 作为浏览器/page/platform action 的前置成功动作；
- 每个窗口写 `runtime-resource-summary.json`，至少记录基线/峰值/终态页面数、writer 实际峰值、进程 RSS、
  `MemAvailable` 最低值、降档和回收原因；
- 在统一工作簿 `性能与外部调用统计` 写实际峰值并发、配置上限和资源门结果；
- 完成门拒绝缺少准入/总结收据、页面超预算、内存越界、压力后反向升档或任务终态页面未回收的 run。

尚未注册这些机器证据的平台任务即使 writer 可调用，也只能 dry-run/只读能力盘点，不得宣称正式实现或完成。
