# 任务分支：资质图与专项图片治理

基于龙猫购等大店 38,000+ SPU 实战全量排查与平台机审验证，总结沉淀全网 48 种特殊图（资质图）槽位映射及跨渠道（美团 100 ↔ 饿了么 200）等价复用规则。

机器唯一策略事实源为 [`scripts/qualification_image_policy.json`](../../scripts/qualification_image_policy.json)。

---

## 核心业务规则：上游生图与跨渠道双向强制复用

1. **允许并优先走上游生图 API**：
   - 资质图/专项图一律允许通过上游生图 API 生成，包含 3C 质量认证（Type 4）、医疗器械注册证/备案凭证（Type 10）、化妆品备案背签（Type 8）等证照类图片；不设置真实材料前置门槛，商品已有可复用图也不再是发起生图的前置门槛；
   - 上游接口、key 配置项、全链路脚本与分证照提示词见 [`upstream-image-generation.md`](../upstream-image-generation.md)；
   - 同一生成 job 按 `(tenant_scope, spu_id, physical_category)` 业务键去重，仅用于避免同一任务重复付费，不限制是否发起新的生图任务。

2. **跨渠道双向强制挂载回填（美团 100 ↔ 饿了么 200）**：
   - 当某个渠道（例如美团闪购）触发生成某物理分类的资质图并上传确权后，**无论对端渠道（饿了么）当前为空或已有图，必须按照等价映射关系双向强制回填挂载到对端对应的特殊图槽位中**；
   - 反之，饿了么渠道缺失图在生成后，亦同步全量挂载至美团对应槽位，做到一次生成、全渠道共享合规。

3. **生成类型集合与防欺诈**：
   - 允许生成的 `picture_type` 集合为：`[3, 4, 5, 6, 7, 8, 10, 13, 15]`，与 `writeback.allowed_generated_picture_types` 必须完全一致；
   - 3C 质量认证（Type 4）与医疗器械注册证/备案凭证（Type 10）等证照类图片一律按各自正式提示词模板生成；不同证照类型的提示词见 [`upstream-image-generation.md`](../upstream-image-generation.md)；
   - `generation.prohibited_legal_content` 只拦截明确含有“伪造”、“假冒公章”、“虚假报告”等欺诈性内容的 prompt，正常证照模板生图不受限制。

## 统一执行链路与写回规范

1. **槽位提取与盘点**：
   - 提取 SPU 在各渠道的 `mtSpecialPictureList` / `elmSpecialPictureList` 实时配置；
   - 计算各渠道的未满足槽位（`missing_slots`）；
   - 按 7 大物理实质类归并去重，得出本 SPU 实际需要补充的最小物理图片集。

2. **上游生成与确权存证**：
   - 按该证照类型的正式提示词模板结合商品名称、类目、规格属性，通过 `run_safe_special_picture_generation.py` 调用上游生图 API；
   - 下载生成图片后通过牵牛花官方 CDN 接口（`/api/v1/image/uploadImageFullType`）上传确权，获取正式 `fileUrl`；
   - 记录任务账本并按 `(tenant_scope, spu_id, physical_category)` 业务键去重，避免重复付费。

3. **双向回填与全门店同步（严守门店自定义主图隔离）**：
   - 依据映射矩阵，将上传确权的 `fileUrl` 同步注入美团与饿了么对应的所有等价槽位数组中（严禁把 `pictureExample` 示例图当成真实资质图写入）；
   - 调用 `update/v2` 接口提交保存时，`fieldCoverageInfoList` 仅允许声明特殊图槽位字段（`mtSpecialPictureList` / `elmSpecialPictureList`）的 `coverToStore: 1`，**严禁携带 `{ field: 'picture', coverToStore: 1 }` 或 `{ field: 'spu_name', coverToStore: 1 }`**，以免误触发主档级联更新冲掉门店的自定义主图（`customizedPicFlag: true`）与自定义名称（`customizedNameFlag: true`）；若目标门店为自定义门店商品，按门店维度独立维护；
   - 必须通过独立回读（`readback`）确认平台已持久化挂载图片且门店自定义主图无损，方可标记为 `verified_complete`。
