# 门店旧新 SKU 替换迁移任务入口

只在用户提供旧门店 SKU 与新主档 SKU 的明确逐行映射，并要求把门店经营资料迁移到新 SKU、删除旧门店商品且确保新商品上架时加载。
这是高影响复合写任务，不等同于通用商品编辑、搬品冲突复核或整店迁移。

## 最小执行流

1. 冻结工作簿、工作表、旧 SKU 列、新 SKU 列、结果列、唯一租户、唯一门店和目标行集合；新 SKU 为空的行不进入 manifest。
2. 当前成功页面请求只读发现覆盖、门店商品、库存、库位、供应商、渠道状态、删除和上下架的真实端点及标识；禁止沿用猜测端点。
3. 保存旧 SKU 的四类源快照，确认新 SKU 唯一存在且尚未与另一旧 SKU 发生冲突；`旧 SKU = 新 SKU` 的行直接进入映射冲突，禁止进入删除集合。
4. 先做一条不含删除的 canary：覆盖新 SKU、迁移四类资料、上架并独立回读。任何字段未闭环则停止。
5. 删除接口按 SPU 生效时，先展开每个待删门店 SPU 的全部规格；只要含一个未进入用户确认集合的 SKU，整 SPU 都必须从删除批次剔除。
6. 在实际触发“删除门店商品及已上线渠道商品”前，展示准确删除数、门店、SPU 展开后的安全行数和 canary 回读结果，取得即时确认。
7. 确认后只删除安全 SPU；异步“任务处理中”只算受理，持续按剩余 SKU 独立回读，最后只回填合同指定结果列。

完整范围、动作顺序、结果词汇与完成门只读[门店旧新 SKU 替换迁移合同](../store-sku-replacement-contract-v1.md)。
